# HR0001: Blank line after a multi-line statement

A statement that spans several lines is followed by a blank line before the next statement in the same block, switch
section or top-level code.

## Why

Code reads in paragraphs. A call whose arguments wrap, an `if` with a body or a wrapped LINQ chain is one step of the
method; without a blank line after it, the next statement looks like part of the same step, and a side-by-side diff
makes the boundary even harder to see. A one-line statement may lead straight into a multi-line one, so a setup line
and the call it prepares stay together.

## Examples

Reported:

```csharp
var order = Order.Create(
    customerId,
    lines);
repository.Add(order);
```

Fixed:

```csharp
var order = Order.Create(
    customerId,
    lines);

repository.Add(order);
```

A comment does not count as the blank line; the fix puts the blank line above it. A directive that closes the
statement, such as `#pragma warning restore`, stays directly below the statement and the blank line goes after it,
together with any comment above that directive. A directive that opens something for the next statement, such as
`#region` or `#pragma warning disable`, gets the blank line above it:

```csharp
#pragma warning disable CA2000
var stream = OpenStream(
    path);
#pragma warning restore CA2000

// The caller owns the stream from here on.
return stream;
```

## Fix

`dotnet format` and the IDE light bulb insert the blank line. Fix All handles a whole file, project or solution.

## Turning it off

In your `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.HR0001.severity = none
```

If HR0001 reports code it should not, please
[report the false positive](https://github.com/Hanif6731/HouseRules/issues/new?template=false-positive.yml) rather
than only turning the rule off.

## Upstream

The rule has been proposed for Roslynator as
[dotnet/roslynator#1849](https://github.com/dotnet/roslynator/issues/1849). If Roslynator ships an equivalent, HR0001
is deprecated in favour of it and this page says which rule to use instead.
