# HR0002: One element per line once a list wraps

An argument or parameter list that breaks after its opening parenthesis (or bracket) puts each element on its own
line. A list that fits on the line of its opening parenthesis stays on one line.

## Why

A list that wraps but keeps its elements together on the next line has no natural line limit, and changing one element
rewrites the whole line, so a diff shows every element as changed. One element per line gives one-line diffs, keeps
each argument readable next to its name, and makes a long list easy to see as the cue to pass one object instead.

A list split part-way, with some elements on the opening line, is reported by
[RCS0053](https://josefpihrt.github.io/docs/roslynator/analyzers/RCS0053). For a list whose elements all share one line,
RCS0053 checks only the indentation, so HR0002 asks for the split; a packed list that is also mis-indented gets both,
and one `dotnet format` run fixes both.

## Examples

Reported:

```csharp
var command = new RegisterCommand(
    body.Email, body.Password, body.AcceptTerms, body.Language);
```

Fixed:

```csharp
var command = new RegisterCommand(
    body.Email,
    body.Password,
    body.AcceptTerms,
    body.Language);
```

Not reported: a list on the line of its opening parenthesis, a list with one element, and a list with an element that
spans several lines, such as a lambda with a block body. A list with a comment between two of its elements is not
reported either, because the comment has no clear place once the elements split.

The rule covers argument lists (including indexer and attribute arguments) and parameter lists (including records,
primary constructors, indexers and lambdas).

## Fix

`dotnet format` and the IDE light bulb put each element on its own line at the indentation the elements already
have. Fix All handles a whole file, project or solution.

## Turning it off

In your `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.HR0002.severity = none
```

If HR0002 reports code it should not, please
[report the false positive](https://github.com/Hanif6731/HouseRules/issues/new?template=false-positive.yml) rather
than only turning the rule off.
